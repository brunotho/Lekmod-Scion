   - Emulate the existing style of both. The changelog uses one section per item: `NAME (TYPE_KEY)`, a dashed underline, a one-line summary, then `- Changed:` / `- Added:` / `- Removed:` lines. Commits use a short imperative title (`Add PROMOTION_X: …`) plus a body when needed.

   - **`changelog.txt` has a dual purpose.** It tracks development (and should line up with the git history), and it is the source for **player patch notes** on a future website. Keep it machine-readable:
     - `## <release>` opens a release block. New work goes under `## UNRELEASED (...)`.
     - Item: `NAME (TYPE_KEY)` + dashed underline + `Tags: a, b` + a short player-facing summary.
     - Player-facing lines: the summary, `- Added:`, `- Changed:`, `- Removed:`, `- Fixed:`. Write them for players with no development knowledge: effects and quick-speed numbers, no column names, C++ names or file paths.
     - **Player lines describe the net change compared to the previous release** (for the current block: upstream LEKMOD v35.4). Example: Heal Instantly "50 -> 25", not "50 -> 40" and then "40 -> 25".
     - Bugs we introduced and fixed before a release never reached players, so they go on `Dev:` lines. Only bugs that exist in the previous release are `Fixed:`.
     - Every line starts with one of the prefixes; no bare lines. Things that are defined but not yet reachable in game (e.g. ungranted promotions) get a `- Note:`.
     - Developer-only lines: `- Note:`, `- DLL:`, `- Dev:` (skipped by the website).
     - **Tags:** the first tag is the item's group (the website's section header); further tags are cross-cutting filters. The header's tag order is the site's section order (user, 2026-10-18: the big reworks first): tourism, world congress, espionage, policies, civs, buildings, units, promotions, religion, city-states, diplomacy and trade, tiles and resources, game mechanics, ui, bugfix; filter-only tags: combat, movement, naval, air, wonders, ruins (the `art` tag was dropped on 2026-10-18, user). Extend deliberately and update the file header too. Lobby settings go under ui. A pure fix gets `bugfix` as its first tag.
     - **Presentation rules (user, 2026-10-18):**
       - The summary is optional. Write one only when it gives a gist the lines don't already say, e.g. the net result of several lines ("1.8 instead of 2"). No restating a single line, no vague lines ("Several units get new strength"), no hype ("the changes speak for themselves").
       - A new item gets `(NEW)` right after its name, `NAME (NEW) (TYPE_KEY)`, not "NEW." in the summary.
       - `Weight: minor` (listed under "Minor changes" at the end of the section) is used **only in Game Mechanics** (user, 2026-10-18: no major/minor split anywhere else). Otherwise cards are alphabetical unless `SECTION_LAYOUT` / `SUBSECTION_ORDER` in `website/build.rb` say otherwise.

       - **Art changes are never in the player notes** (user, 2026-10-19): new icons, portraits, 3D models, pictures, looks go on `Dev:` lines (a card with only Dev lines is hidden; remove it from `SECTION_LAYOUT` then).
       - No developer words in titles or lines: file names, pixel sizes, "(FORMULA CHANGE)". Numbers are always quick-speed, as in the specs (the game data holds standard values; players only care about quick).
       - A fix that isn't confirmed in game is worded as an attempt ("An attempted fix, not yet confirmed…", "should now…"), e.g. the aircraft count.
       - Fixes to things that are new in the same release (e.g. their icons) never reached players: `Dev:` lines.
       - Filter tags group across sections, e.g. `wonders` on every wonder card wherever its section is.
       - **Big reworks read rules first** (user, 2026-10-18): World Congress = new proposals, changed proposals, mechanics (sessions, Delegates), rest; Tourism = "The rules", then "Where Great Works and Tourism come from" (wonders last there), then the policy collection. Small fixes of a rework (e.g. tile icons) go to Bugfix, not into the rework's section. Promotions are split into "you can pick" and "come with units, policies or abilities" by the loaded DB (`CannotBeChosen` 0 and at least one `UnitPromotions_UnitCombats` row = pickable); a new promotion card must be added to one of the two lists. A minor card listed in a layout block stays in that block, after its major cards.
       - **Civ cards: lines in the order UA, start bias, UI, UB, UU** (user, 2026-10-18). Writing rules (user, 2026-10-18, second round):
         - **One entry per item.** The UA, each unique improvement, building and unit appears in exactly one entry; never an Added, a Changed and a Removed line about the same item. Several changes = a head line ending in ":" with `  - ` sub-items; what it lost is the last sub-item, `  - no longer: …`.

### 2b. Cloud sessions: how they work (verified 2026-10-15, session 5)
- **Setup:** the session gets the repo via the GitHub connection (`brunotho/Lekmod-Scion`, cloned shallow on branch `dev`, ~880 MB). Notion is connected (same workspace and tracker as locally); the connection sometimes drops for a while and comes back.
- **Pushing:** the user allowed cloud sessions to **push their commits to `origin/dev` after each batch** (2026-10-15), because the container is temporary and the local session must see the work. `git fetch origin dev` before pushing. Author commits as the user (`git -c user.name="Bruno Thormählen" -c user.email="brunothormaehlen@yahoo.com" commit ...`) plus the Co-Authored-By trailer, like the local commits. Local sessions: `git pull` first.

## 3. How the game loads the mod (verified)
The folder is a **DLC package** (`MPModsPack.Civ5Pkg`), not a ModBuddy mod:
1. **`CvGameCore_Expansion2.dll`**: the compiled game core (all rules, combat, ruins, World Congress…). It replaces Firaxis's. Built from `LEKMOD_DLL/` (§5).
2. **`Override\`**: each file replaces the base-game file of the **same name**.
   - About 520 files there are **empty** on purpose. They blank out base-game data.
   - **`Override\CIV5Units.xml`** (~308k lines) holds **all gameplay data** for every table (units, promotions, ruins/GoodyHuts, policies, World Congress, icon atlases, `<Table>` column definitions…). The file name is misleading.
   - **`Override\CIV5Units_Mongol.xml`** (~145k lines) holds **all text** (`Language_en_US`, using both `<Row Tag>` and `<Replace Tag>`).
3. **`Lua\UI\*.lua`** (and some `.xml`): UI files. They override the base-game UI file of the same name, e.g. `GoodyHutPopup.lua` = the ruin reward popup.
   - **`Lua\UI\` is generated output.** Players are told to run `ui_check.bat`, which **deletes `Lua\UI\` and rebuilds it** by copying templates from `Lua\tmp\ui\...\*.ignore` (standard UI) or `Lua\tmp\eui\...\*.ignore` (when EUI is installed as `DLC\UI_bc1`).
   - **Edit the template** and sync it into `Lua\UI\`, otherwise the next `ui_check.bat` run silently reverts the change.
   - The user runs the standard UI (no EUI folder).
   - Base-game UI layouts that Lekmod doesn't override come from `Assets\DLC\Expansion2\UI\InGame\...`. Overriding one means adding the XML to the templates, to `ui_check.bat`, and to `Lua\UI\`.
   - Base-game scripts Lekmod overrides since 2026-10-08: `CivilopediaScreen.lua` (both UIs), `DiploList.lua` (standard UI; `ui_check.bat` copies it unless EUI has its own) and `ChooseGoodyHutReward.lua` (both UIs; the ruin choice); since 2026-10-10 also `PlotHelpText.lua` (standard UI only) and `UniqueBonuses.lua` (front-end civ lists; the base file crashes for a civ with fewer than two unique items, e.g. England after the naval rework, which aborted the single-player civ list: check this whenever a civ loses a unique); since 2026-10-12 also `LeagueOverview.lua` (Congress screen), `Demographics.lua/.xml` (Blackout) and `EspionageOverview.lua/.xml` (spy rework); all three are copied for both UIs; since 2026-10-14 also `CityStateDiploPopup.xml` (standard UI only: Mexico's third tribute button; the Lua checks `Controls.InfluenceTributeButton ~= nil` so EUI's own layout still works); since 2026-10-17 also `SelectCivilization.xml` (5 unique-item slots) and `UnitPanel.xml` (hotkey label on action buttons), both standard UI only, copied by ui_check together with their Lua, and `MultiplayerSelect.lua/.xml` (the streamlined Multiplayer menu, both UIs; template in `Lua/tmp/ui/FrontEnd/`) and `OtherMenu.lua/.xml` (Main Menu > Other with "Multiplayer: Other Modes", both UIs). **A feature that needs new C++ only works when ALL of these hold** (names must match exactly):
- the column is defined in `CIV5Units.xml` (`<Table name="X"><Column .../>`), and values are set in `CIV5Units.xml`
- the text is in `CIV5Units_Mongol.xml`
- the C++ reads the column **by name** (`kResults.GetInt("Col")` in `CacheResults`)
- the DLL is **rebuilt and installed**
- (optional) Lua UI displays it, and the Lua logic matches the data

## 4. Data conventions and gotchas
- **Promotion IDs are explicit** (`<ID>`). Every row in the `UnitPromotions` section has one. New rows get the next unused ID: currently up to **393** (391 Blessed (Tibet), 392 Nau Escort (Portugal), 393 Expanded ZOC). v35.4 uses IDs up to 343; ours are 344–393. Upstream's IDs already have gaps (e.g. 271–273), which is fine. Check uniqueness *within the section*, since other tables reuse the same numbers.
- **Line endings differ per file and change over time; detect them in every script, never assume.** The repo stores LF (`git ls-files --eol`: `i/lf`). With `core.autocrlf=true` a checkout writes CRLF, so files git rewrote locally (e.g. after a `git pull` of cloud commits) turn CRLF. On 2026-10-16 **both Override XML files, `_Defines.h`, `changelog.txt` and `CLAUDE.md` were CRLF** (`w/crlf`), although they were LF on 2026-10-08. Scripts: read bytes, note whether `\r\n` occurs, work on `\n`, and write back with the ending found (`cpp_edit.py` does this; `helpers.py` and other older scripts may still assume LF, check them before use). The game reads either.
  - Prefer the Edit tool, which keeps a file's endings.
  - When scripting, read and write **bytes** and match the file's ending. Count with Python (`b.count(b'\r\n')`); `grep -c $'\r'` in Git Bash gave wrong answers.
- **Tooling pitfalls (cost time repeatedly):**
  - **Bash heredocs mangle backslashes, quoted ones (`<<'EOF'`) too** (`\\` collapses, `\U`/`\N`/`\s` break Python strings; on 2026-10-16 `"\r\n"` inside `python - <<'EOF'` became real line breaks twice). Write Python scripts with the Write tool into the scratchpad (raw strings), or use the Edit tool. Never put Windows paths or regexes with backslashes into a heredoc.
  - **The Edit tool rewrites non-UTF-8 bytes** (e.g. the Firaxis header's copyright byte in some `.h` files becomes U+FFFD). After editing C++ headers, check `git diff` for a changed line 2 and restore it from `git show HEAD:<file>`.
  - Byte-safe C++ edits: the scratchpad helper pattern `cpp_edit.py` (exact-once anchors, keeps CRLF and non-UTF-8 bytes) worked well; recreate it if the scratchpad is gone.
  - Unit combat strength has two parallel code paths in `CvUnit.cpp` (old `GetMaxAttackStrength(pFromPlot,...)` and v35.4's `GetMaxAttackStrength(const CvCombatInfo&...)`, same for defense/ranged). With `LEKMOD_COMBAT_PREDICTOR_IMPROVEMENTS` on, the old path is compiled out (`#if !defined(...)` around it, verified 2026-10-11 by a link error): only the `CvCombatInfo` path is live. Keep new modifiers in both anyway, but helper functions must not sit inside the disabled block.
  - **`sed -i` strips CRs** from CRLF files (the C++ sources). Use the Edit tool or Python byte I/O.
  - **The Write tool strips trailing whitespace**, and many Override lines end with a space (`<Row> `, `</Table> `). Use short anchors without line ends, or match by regex.
  - **A repeated column inside one `<Row>` makes the game drop the whole Override file** (Database.log: "Duplicate column names detected in <Row>", then "no such table" everywhere and a crash at Play Now; 2026-10-10, spaceship parts already had `CombatLimit`). After scripted row edits, parse both Override files with Python's ElementTree and check every `<Row>` for repeated child tags.
  - **XML tables contain commented-out `<Row>` blocks.** Row-editing scripts must skip `<!-- ... -->` regions (2026-10-08: a script edited commented rows; caught in the diff).
  - **Order matters for appended data blocks (2026-10-11):** `CIV5Units.xml` re-creates tables with `<Delete />` at their first data element, and the big `Buildings` (~43k), `Units` (~271k) data come late. An `<Update>`/`<Row>` placed before a table's wipe or before its rows exist silently does nothing. Put building data right before `<Table name="Builds">`, unit updates after the last `<Units>` element, belief data after `</Beliefs>`; check with a script that no LEKMOD block precedes a full `<Delete />` of the same table.
  - Bulk value changes to existing rows can be done with `<Update><Where Type="X"/><Set Col="v"/></Update>` blocks after a table's section (used for building purchase costs and tech costs). Later per-row changes must then edit those Update values, not the original rows.
- **Compiled-out duplicates bit again (2026-10-11):** `CvCity` local happiness has a policy building-happiness loop under `#if !defined(LEKMOD_NONCIV_BUILDINGCLASS_YIELD_CHANGE)` (dead) and a live one after `#else`. Sovereignty's happiness went into the dead one. After writing hooks, list the enclosing `#if` stack of each hook (scratchpad script idea: walk the file, track `#if/#else/#endif`) and check every condition is defined.
- **`_Defines.h` has `#define`s inside `/* */` comments (2026-10-15), and they are OFF:** `AUI_CONSTIFY`, `NQM_PRUNING`, `AUI_WARNING_FIXES`, `AUI_ITERATORIZE`, `AUI_CITIZENS_GET_VALUE_CONSIDER_GROWTH_MODIFIERS` and ~200 more (the block at lines 28-69 and others). So the non-const branches of `#ifdef AUI_CONSTIFY` headers are the live ones (new `CvCityReligions` methods must go after that `#endif`, non-const), and `CvPlayer::canBuild`'s live tech check is the `#else` of `AUI_WARNING_FIXES` (Maurya's turn-1 Roads and the policy-pick Culture freeze had sat in dead branches since batch C / Phase 5). `tools/dev/ifstack.py` used to count commented defines as live; it now strips comments. **`tools/dev/deadcode.py`** lists every Lekmod line in a dead branch; run it after each C++ batch (most hits are old upstream duplicates; filter to our commits with git blame).
- **UI facts found 2026-10-12/13:**
  - The largest UI font is `TwCenMT24` (14/16/18/20/22/24 exist; no bigger sizes). For a bigger word, space the letters out.
  - Base-game UI textures (e.g. `Esp_FramedIcons45_Expansion.dds`) are packed in the game's `.fpk` archives, not loose files. To get a matching icon, draw it (see `art_sources/tools/build_levelup_icon.py`).
  - Hotkeys of screens come from the `Controls` table (`HotKey` = `KB_F2`…`KB_F9`; Advisor Counsel, Trade Routes, Espionage and World Congress have none).
  - Leading spaces in label/tooltip lines are kept (used for indents and the hanging indent).
  - **Multiplayer (and the user's testing) always runs Quick Combat and Quick Movement** (user, 2026-10-19). Don't build UI on `Events.RunCombatSim` / `EndCombatSim` (combat animation events, probably skipped with Quick Combat); gate or time the player's click instead (the air strike delay notes the strike at the click in InGame's `InputHandler`; a detector watching planes run out of attacks restarted it late, by the network lag). After a strike the game auto-selects the next unit, and right-click attacks in selection mode have no Lua handler (the engine runs them), so limits on Tab alone don't limit strikes.
  - The Demographics/Congress-style screens keep their frames; a full-size opaque box over them looked broken (black box overlapping the frame). Hide content instead of covering it.
- **Game-core log files don't appear** on this PC (`LekmodCongress.log` etc. via `LOGFILEMGR` never showed up, although `LoggingEnabled = 1`). For diagnostics use Lua `print` (Lua.log) or data the UI can show.
- **Lua checks without the game:** `pip install lupa` gives a Lua runtime in Python. Load a template's helper functions with `LuaRuntime().execute(...)` to unit-test them, and parse a whole file by wrapping it in `return function() ... end` (replace `include(` first). Used for the policy tooltip hanging indent.
- **Images can't be shrunk in the Civ V UI** (as far as verified): `SetTextureSizeVal` + `NormalizeTexture` only crop (base `CultureOverview`, `MPTurnPanel`). Use an atlas size that exists (promotion atlases: 32/45/64/256). `IconHookup` always returns true once the atlas exists.
- **Website `site.js`: the filters select `#changelog article.card`.** Anything else with the CSS class `card` inside `#changelog` (the Essentials box) broke search and tags on 2026-10-22 (no tags -> script error).
- **Duplicate function copies behind defines (2026-10-10):** `CvTradeClasses.cpp` has two versions of the trade value functions; `TRADE_REFACTOR` (on) selects the data-driven ones near line 2350–2910, the old ones further down are dead. Before editing a function, grep for every definition of its name and check which `#if` branch is compiled. The sea +100% trade bonus is data (`TradeConnections_DomainYieldModifiers`).
- **Notification panel layout:** the small-notification `SmallScrollPanel` always takes the full remaining height (`g_SmallScrollMax - bigY`), so anything stacked above it lands at the top of the screen. The dismiss-all button sits between `BigStack` and the scroll panel, and its height is subtracted.
- **Broken upstream helpers / engine quirks (2026-10-09):** `CvCityBuildings::HasBuildingClass` always returns false (its list `m_buildingsThatExistAtLeastOnce` is never filled); loop the class's buildings with `GetNumBuilding` instead. `SetNumFreeBuilding` doesn't notify the renderer (walls/wonders don't appear until reload); call `gDLL->GameplayWallCreated` etc. yourself.
- **Strategic node sizes** live in the mod (`Resources.AmountMajor/AmountMinor`) and are read by the map script; the Lekmap copy in this repo still hardcodes them (the user's map folder is the authority). An earlier conclusion here that they were map-only was wrong.
- **City-count tech and policy costs (verified 2026-10-22):** tech cost x (1 + 5% x cities), policy cost x (1 + 10% x cities) on Duel-Standard maps (`Worlds.NumCitiesTechCostMod/PolicyCostMod`; Large 3.75/7.5, Huge 2.5/5). The city count is `CvPlayer::GetMaxEffectiveCities`: the highest number of non-puppet cities ever held (`m_iMaxEffectiveCities`, saved, never goes down); cities being razed or awaiting the capture choice don't count. Tech costs use max(that peak, current cities incl. puppets) (`FIX_MAX_EFFECTIVE_CITIES`); policies use the peak only.
- **Valid text icons:** `[ICON_PEACE]` = Faith (`[ICON_FAITH]` does **not** exist). `[ICON_EXPERIENCE]` and `[ICON_HEALING]` do **not** exist.
  - The authority is the loaded `IconFontMapping` table in `Civ5DebugDatabase.db` (884 icons).
  - Don't judge by whether a tag appears in any text: `[ICON_STAR]` is valid but appears in no text.
  - Being in the table is not enough: `[ICON_WONDER_HEROIC_EPIC]` is listed but renders as a gap (user, 2026-10-11). Prefer icons already used in visible texts; wonder icons are unreliable.
- Text keys must be unique. Check `CIV5Units_Mongol.xml` before adding a key; existing keys may already be used by other content (e.g. `TXT_KEY_PROMOTION_DISCIPLINE`).
- Numeric text placeholders: `{1_Num}`. A text that expects a number but gets none renders **blank**.
- **Game speed: always assume QUICK.** The user only plays quick speed, and their specs state quick-speed numbers.
  - When a formula involves game speed (culture, faith, production costs, turn counts…), check how speed scaling affects it, and make the result match the spec *at quick speed*.
  - Other speeds don't matter.
- **Text style (user preference) for all player-facing text** (tooltips, popups, pedia):
  - **Be greedy with spacing for readability.**
    - Each sentence goes on its own line (`[NEWLINE]`).
    - Distinct topics or effects are separated by an empty line (`[NEWLINE][NEWLINE]`), e.g. bonus vs. penalty, or combat vs. movement.
    - This applies to all new and changed tooltips. Older tooltips will be retrofitted later (user's intention).
  - **Policy tooltips (user, 2026-10-11):** every non-ideology policy is `Name` + `[ICON_BULLET]` lines. `SocialPolicyPopup` (both UIs) wraps long bullet lines itself (`LekmodHangingIndent`) so wrapped text lines up under the first line. It estimates pixel widths (per-letter table x1.18, icons 22 px, calibrated against a screenshot) and fills lines to 275 px; the game's own tooltip wrap is about 300 px, and anything the game wraps itself starts at the left edge. Indent is 5 spaces (~22 px). The tooltip on a branch **picture** comes straight from XML (no Lua) and wraps at ~275 px, so the branch help texts (`TXT_KEY_POLICY_BRANCH_*_HELP`) are pre-wrapped in the text file: after editing one, rerun `python tools/wrap_branch_texts.py` (rerunnable; it undoes its old breaks first).
  - **Policy tree tooltips (user, 2026-10-11):** opener and finisher effects as `[ICON_BULLET]` lists ("Adopting X:" / "Completing the X tree:"), one effect per bullet, no chains of "and" between distinct effects.
  - **Beliefs (user, 2026-10-11):** one line per effect/sentence (`[NEWLINE]`), no bullets, no empty lines. Bullets with a hanging-indent pantheon popup were tried and dropped (rows overlapped).
  - **Exception:** list or menu rows with fixed height, like the Shoshone ruin choice (`ChooseDescription`), must be short, matter-of-fact one-liners.
  - No spec or implementation notes ("Eligible: naval melee", "Requires Bombardment II", "policy-granted"); the UI shows those itself.

```
& "C:\Program Files (x86)\Microsoft Visual Studio 9.0\VC\vcpackages\vcbuild.exe" "LEKMOD_DLL\CvGameCoreDLL_Expansion2\CvGameCoreDLL_Expansion2.vcproj" Release *> C:\Users\bbruno\civ-tools\build_release.log
```
- Takes a few minutes. Run it in the background. "0 error(s)" with ~780 warnings is normal.
- Output: `LEKMOD_DLL\CvGameCoreDLL_Expansion2\BuildOutput\VS2008_ReleaseWin32\CvGameCore_Expansion2.dll`.
- VS2008 has a **~260-character path limit**, so the checkout must stay at a short path. The scratchpad path is too long.

**Install:**
1. Civ V must be **closed**; the DLL is locked while the game runs. Ask the user, and never kill the game.
2. Back up the current DLL to `civ-tools\dll_backup\`.
3. Copy the build output to `LEKMOD\CvGameCore_Expansion2.dll`. Through the junction, that file *is* the game's DLL. Compare md5 checksums.
4. Commit the DLL (convention: a separate `Rebuild CvGameCore_Expansion2.dll` commit).
5. Start a **new game** for every test. Old saves break when the DLL adds saved fields.

**Windows Smart App Control** blocks unsigned, unknown DLLs. A blocked load shows up as a crash before the main menu, and `Logs\GameCore.log` says *"LoadLibrary failed with error 4551: An Application Control policy has blocked this file."* The user turned it **off** on this PC (2026-10-05). Players with it on hit the same issue with any fresh unsigned Lekmod DLL. The upstream norm is documentation; the real fix is code signing.

## 6. Verification toolkit (use it; don't trust impressions or code reading alone)
- **Loaded data:** `cache\Civ5DebugDatabase.db` (SQLite; query with Python `sqlite3`). It is written at game startup and **matches what the running game uses** (verified with a Lua diagnostic). Text lives in `cache\Localization-Merged.db` (`LocalizedText`, `Language='en_US'`).
  - Caveat: effects **computed in C++** don't appear there (e.g. hardcoded ruin formulas).
- **Logs** (`Logs\`):
  - `Database.log`: XML load errors. The garbage "unrecognized token" and `ArtDefine_StrategicView ... not unique` lines are pre-existing noise.
  - `Lua.log`: Lua errors and `print()` output. Pre-existing noise: Lekmap `FeatureGenerator` and `Demographics.lua manyinclude` errors.
  - `GameCore.log`: DLL load problems.
  - `stopwatch.log`: load phases.
- **Crash dumps (2026-10-10, worked):** a crash writes `CvMiniDump_<date>_LEKMOD.dmp` into the game folder. `pip install minidump pefile`; read the exception address and module (offset into `CvGameCore_Expansion2.dll`). The release build has no PDB/map, but relinking the existing objects with `/MAP` reproduces an identical `.text` section: scratchpad script `relink.py` (takes the link command from `BuildTemp/.../BuildLog.htm`, runs `link.exe` from the project dir via `vcvars32.bat`), then map the offset and scan the crashed thread's stack for return addresses into the DLL (`stackscan.py`). Do this right after a build, before the objects change.
- **Lua diagnostic trick:** add a temporary `print("TAG", ...)` to a UI script that runs at the right moment (e.g. `GoodyHutPopup.lua`), have the user trigger it in game, then `grep TAG Lua.log`. Back up the file first, and remove the print afterwards.
- For gameplay checks, give the user **concrete expected values** (formulas → numbers) to compare against, then cross-check the database and logs yourself.

## 8. Failure patterns found in the fork (check new work for these)
1. **Data placed where the game doesn't read it**: XML under `Art\`, `.modinfo` edits.
2. **C++ never compiled.** April C++ only reached the game on 2026-10-05; a June "compile fix" actually broke compilation.
3. **Parallel duplicate implementations.** The ruins overhaul existed as a hardcoded draft (slipped into the Amphibious commit `18d18874`) **and** a column-based version (`4f6af0bb`). They came from separate branches merged together.
4. **Unrelated changes bundled into commits.** E.g. "reduce Heal Instantly" also rewrote the faith ruin's data. Don't trust commit titles; diff the commit.
5. **Data changed without its consumers.** The ruin popup Lua picks its text by data fields that the data change made zero, so the popup came out blank.
6. **Dead edits**: targeting rows that aren't used (`GOODY_EXPERIENCE` vs the live `GOODY_EXPERIENCE_MOVE`), and promotions that nothing grants (see §9).
7. **Upstream bugs exposed by new content**, e.g. the kill-yield era flags (fixed, §9).
7b. **Balance tweaks without text updates.** Coastal Raider, Boarding Party, Heal Instantly (`INSTA_HEAL_RATE` define) and others changed numbers only, so their tooltips lied.
   - After any value change, diff the tooltip.
   - For promotions, verify the help text against the loaded DB values.
7c. **Wrong cross-references.** Bunker Busting's bomber prerequisite pointed to `PROMOTION_SIEGE` (a melee/gun promotion) instead of `PROMOTION_AIR_SIEGE_*`.
   - Check prerequisites against `UnitPromotions_UnitCombats` of the same unit type.
7d. **Off-by-one in new C++.** The Amphibious "max moves after domain change" formula left 0 MP instead of 1. Sanity-check new formulas with concrete numbers.
7e. **Changes on the unplayable copy of a civ.** Some civs exist twice in the data: the playable Lekmod row and an unplayable base-game row. **Venice is `CIVILIZATION_VENEZ`** (leader `LEADER_VENEZ`); `CIVILIZATION_VENICE` / `LEADER_ENRICO_DANDOLO` / `TRAIT_SUPER_CITY_STATE` are unplayable leftovers. Batch I (2026-10-14) put Masks and Mirrors on `TRAIT_SUPER_CITY_STATE`, and its DB check passed because it checked the trait row, not that a playable civ has it; the playable Venice kept Serenissima, also in 1.0.0. The website civ list (which reads the playable civ, correctly) showed it on 2026-10-20. Before changing a civ, find its trait via `Civilizations.Playable = 1` -> `Civilization_Leaders` -> `Leader_Traits`; `website/test/changelog_test.rb` (`test_civ_changes_target_playable_civs`) now fails for a trait `<Update>` or a changelog civ card on a civ no player can pick.
8. **AI art**: icons with baked backgrounds, and one image reused for several promotions.
9. **Upstream code that bypasses our hooks after a merge.** Our code merged cleanly but never ran: in v35.4, a new early return in `ConsumesAllMoves` bypassed Amphibious. After an upstream merge, re-read the functions around each of our hooks and retest every feature, not only the conflicting files.

**Debugging lesson:** twice a confident conclusion was wrong. "Zealot will work" was wrong; "the ruins aren't changed at all" was half wrong, because the C++ computed the effects. When the user's observation conflicts with your model, find a direct measurement (database, log, diagnostic) before arguing.

### Behaviour and decisions to remember
- **Unit screens and air combat UI (2026-10-19/20, user's chat specs; all Lua, screen-local, nothing sent over the network):**
  - Files: `Lua/tmp/ui/InGame.lua.ignore` (target tile, Tab, strike delay, range outline, panel hotkeys), `Lua/tmp/ui/UnitList/UnitList.lua/.xml.ignore` (unit list, both UIs), `Lua/tmp/ui/MilitaryOverview/MilitaryOverview.lua/.xml.ignore` (F3; Lekmod's own override since 2026-10-19, standard UI only), `Lua/tmp/ui/Highlights.xml.ignore` (styles `LekmodTargetTile`, `LekmodAirRangeOutline`). None of their `Lua/UI` copies is tracked. Texts: block "LEKMOD: unit list and Military Overview" at the end of `Language_en_US`.
  - **Promotions column** (both screens, replaces Status): `LekmodChosenPromotions` = pickable promotions (`CannotBeChosen` 0, with an icon) the unit type doesn't start with (`Unit_FreePromotions`); policy/upgrade ones show too (the game doesn't record a promotion's source). Icons 32 px, overlap when they don't fit (`LekmodShowPromotions`), names in the row tooltip; header sorts by count. The Status texts are still computed (name-sort tiebreak) but hidden. Military Overview also has an HP column (colored like the unit list).
  - **Target tile:** Alt + left click (in `ClickSelect`, before `UI.LocationSelect`) tags a tile, again = clear; "Clear tagged tile" button in the Military Overview. `LuaEvents.LekmodTargetTileChanged(x, y)` (-1 = clear) tells both screens; they show a "Dist." column (air units only) and sort (`LekmodDistanceLess`): units out of moves or attacks last; else in strike range (`unit:Range()`, hex distance from the plane's tile, carrier tile for planes on carriers) farthest first, then out of range closest first (number dimmed, alpha 0.4), then other units by name. Re-highlighted after the city screen and at turn start.
  - **Tab** (while a tile is tagged; `LekmodTabNextPlane`): next plane in strike range that `CanMove` and not `IsOutOfAttacks`, no nukes, same order as the list; wraps; restarts on a new tag and each turn; select only (no strike mode, camera stays). The chat toggle lost its Tab hotkey (`CONTROL_TOGGLE_CHAT` row in `CIV5Units.xml`; both DiploCorners read it from the Controls table).
  - **Strike delay** (`LEKMOD_STRIKE_DELAY` 0.5 s, `LEKMOD_TAB_DELAY` 0.45 s, trial values): `LekmodAirStrikeClick` in InGame's `InputHandler` swallows a strike click (right button in selection mode, left button in strike mode; decided on button down, the button up follows) when the selected air unit `CanRangeStrikeAt` the tile and the last strike was < 0.5 s ago; it applies always, not only with a tag (the game auto-selects the next unit after a strike, so a Tab-only limit didn't slow strikes). Tab waits 0.45 s after the last Tab and 0.5 s after the last strike. The strike time is noted at the click only; a detector that watched planes run out of attacks restarted the delay late (network lag) and was removed. `os.clock()` is used as the timer (MSVC: wall time).
  - **Strike range on selection** (`LekmodShowSelectedAirRange`): a selected air unit that `CanRangeStrikeAt`/`CanRangeStrike` (no nukes) shows its range as a red outline (style `LekmodAirRangeOutline`) in selection mode only; strike mode keeps the base red area (`AirStrikeHighlight`, Bombardment.lua).
  - **"Air units only" checkbox** in both screens (`LekmodUnits` filters the unit loop), kept in sync with `LuaEvents.LekmodAirOnlyChanged`; not saved.
  - **Panel hotkeys** (`LekmodInfoCornerHotkey`): Shift+F2 City List, Shift+F3 Unit List, Shift+F4 Resource List, Shift+F6 Research Info, Shift+F9 Great Person List, again = close (`Events.OpenInfoCorner`); tooltips `TXT_KEY_IC_*` name the keys.

- **Amphibious**: I = flat embark cost, II = flat disembark cost, and I and III each add +1 to `MaxMovesAfterDomainChange` (it sums: with I–III, at most 2 MP are left after a domain change). The flat cost is 1 MP, capped so that at most that many MP remain (in both cost functions). `ConsumesAllMoves` lets flat-cost transitions through, and `CvUnit::move` skips `finishMoves()` for them. Walk-water tiles (pontoons, shallows) count as land on both sides of the check.
